Each remaining bin is one relation. The count that matters is not images but
TASKS -- a task is a finding, and the conditions are split train/val/test so that
the relation rather than the task is what generalises.

  a task needs, per its own source side: M_S=64 (+32 query if training)
  and per relation on the target side:   20 reserve + 24 held-out query = 44

verdict
  PASS. 3 relations (0-30, 30-45, 60-75) against source 45-60,
  10 usable tasks, suggested 4/3/3.
  Episodes per K_T on the test side: 3 tasks x 3 relations = 9.

  Compare what this replaces. Fitzpatrick17k gave 3 test tasks and ONE relation,
  and one relation is why C4 failed: the same shift applies to every episode, so
  a constant coordinate solves the meta-objective and the correct source task is
  worth nothing. Several relations is the structure CIFAR had, where the method
  works. That, not the image count, is the reason to switch.

  Still to check before trusting a headline, and none of it needs the images:
    - between-task variance dominates, so count episodes as tasks x relations
    - AP and PA views are different imaging geometries; a view imbalance across
      age bins would be a confound riding along with the population shift
    - sex is recorded and is a second candidate population axis
